# Как работаем

## Взять задачу

1. Открой доску Projects или [Issues](https://github.com/backend-school1/mentordesk/issues). Начинать лучше с `good first issue`.
2. Проверь раздел «Зависит от»: если задачи оттуда не закрыты, бери другую.
3. Назначь задачу на себя. **Одновременно — только одна задача.**

## Сделать

1. Ветка от `main`: `issue-<номер>-<коротко>`, например `issue-2-csv-import`.
2. **В первые 2 дня открой draft PR** с `Closes #<номер>` в описании — даже если там один коммит. Так видно, что работа идёт, и если ты пропадёшь, другой продолжит с твоего места.
3. Пуши часто, маленькими коммитами.
4. Готово — переведи PR из draft в Ready for review и заполни «Как проверить».

## Правило 7 дней

Если по задаче 7 дней нет движения — ни в issue, ни в связанном PR, — бот снимает исполнителя и ставит `help wanted`. Это не штраф: задача просто снова свободна. Вернулся — возьми снова.

## Ревью

- В `main` напрямую не пушим, только через PR.
- Нужен зелёный CI (сборка, тесты, `dotnet format`) и одобрение ревьюера.
- Ревьюить чужие PR — тоже часть работы: один чужой PR в неделю.
- Замечание ревьюера — не приговор: обсуждаем в комментариях.

## Агенты

Claude Code, Copilot и другие агенты использовать можно и нужно. Но в PR ты отвечаешь за каждую строку: на ревью спросят «почему так» — объяснять тебе, не агенту.

## Демо

На еженедельном созвоне каждый показывает, что смерджил за неделю.
